# Security review

Review the pull request for concrete security bugs introduced or materially
worsened by the change. Trace attacker-controlled input and sensitive data through
parsing, wrapping, guards, intermediate calls, and actual sinks. Use available
dependency source instead of assuming safe defaults. Before returning no findings,
make a second pass over changed trust boundaries and resolve missing links in
concrete data flows. Safe client responses alone do not establish that diagnostic
or outbound paths preserve secrets. Unavailable unrelated source must not suppress
a finding supported by inspected code; state its prerequisites and uncertainty.

Check authentication, authorization and tenant isolation, injection, network
destinations and redirects, filesystem boundaries, credential handling including
diagnostics, cryptographic verification, and resource exhaustion where relevant.
Consider removed guards as well as added behavior. Each finding's trigger must
identify attacker-controlled input and prerequisites. Exclude general correctness
bugs. Explain the impact and a practical mitigation for each finding. Do not
claim a complete security audit.
